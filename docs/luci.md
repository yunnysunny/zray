# OpenWrt 图形界面

Zray 页面位于 OpenWrt 的“服务 → Zray”。界面沿用 LuCI 的样式，分为“代理 / 节点 / 设置”三页，交互参考 [Passwall](https://github.com/Openwrt-Passwall/openwrt-passwall)。

## 安装

在 OpenWrt 的“系统 → 软件包 → 上传软件包”中选择与路由器处理器匹配的 Zray `.ipk` 文件。软件包包含 Zray 程序、图形界面、节点管理和透明代理服务。安装器通过 OpenWrt 官方软件源安装所需的组件。

升级时保留已有节点。原有的 `/mnt/zray/config.json` 中包含有效 REALITY 节点时，安装器会将其导入节点列表。安装包中的默认配置不含个人节点或凭据。

## 添加节点

1. 打开“服务 → Zray → 节点”，点击“添加节点”；没有节点时首页也提供此入口。
2. 粘贴服务商提供的完整 `vless://` 分享链接，点击“一键导入”。
3. 回到“代理”页，确认已选中需要使用的节点。

支持标准 VLESS 分享链接和使用 Base64 编码地址的链接。可以一次导入最多 20 个节点，每行一个；任何一条链接格式错误时，会标明位置，整批节点均不会保存。重复导入同一个节点会更新已有记录。

没有分享链接时，选择“手动填写”，输入服务器地址、端口、UUID、公钥和 SNI。节点名称与 Short ID 可以留空。端口默认使用 443。

当前支持 VLESS + REALITY + XTLS Vision，传输方式为 TCP。导入其他协议、安全模式或传输方式时，页面会说明原因。

## 主开关

开启主开关后，系统自动启动代理、检测节点连接、配置透明转发和加密 DNS。连接当前路由器的设备无需填写代理地址。

开关点击后立即反馈正在处理的状态。连接检测及服务配置在后台执行，服务启动后显示“已开启 · 等待检测”，只有近期连通检测成功才显示“已开启 · 连通正常”；网络连接需要实际建立，因此服务生效时间受节点延迟和 DNS 响应影响。处理期间可以再次切换主开关，系统按最后保存的状态执行。

关闭主开关后，系统删除透明转发规则、停止对应服务，并恢复启用前保存的 DNS 设置。启用失败时保留用户期望的开启状态、显示错误并尝试后台恢复；默认清理规则、恢复原有 DNS，允许普通直连。只有明确选择并确认“断网保护”才会阻断所选设备的外网，路由器自身的恢复连接不受阻断。停止服务或清理规则失败时，仍继续尝试 DNS 恢复并保留全部错误。

局域网、路由器管理页面和节点服务器地址保持直连。公网 IPv4 TCP 流量经过当前节点。UDP 443 会被拒绝，使支持重试的客户端改用 TCP 访问 HTTPS。其他 UDP 流量按路由器原有规则处理。

## 节点管理

“节点”页支持选择和检测节点，编辑、删除及服务器详情收在每行的“⋯”中。节点超过 5 个时显示搜索框；订阅、批量检测和备份收在顶部“更多”中。开启代理时切换节点会自动重新配置服务。保存不影响当前连接参数的内容时，会保留正在运行的代理进程。

正在使用的节点需要先停用或切换到其他节点，才能删除。删除操作需要在页面中再次确认。

“设置”页包含分流与设备、DNS 与恢复，以及默认折叠的高级设置和诊断。资源仅在打开诊断或点击刷新时读取，首页不会轮询。插件不保存历史日志；连接失败、DNS 异常和断网保护风险仍会明确提示，诊断保留当前错误。详见 [低存储运行约定](no-logs.md)。修改分组设置时，未显示的配置字段会原样保留。

## 构建

需要 Node.js、Python 3，以及系统的 `file` 命令。

```sh
npm test
python3 tools/build_openwrt.py --binary zig-out/bin/zray --arch mipsel_24kc
```

软件包默认写入 `dist/`，同时生成 SHA256 校验文件。构建过程使用 Python 标准库处理归档格式，并检查输入程序的处理器架构。

GitHub Actions 会运行链接解析测试、编译 Zray，并为配置的处理器生成软件包。其他处理器的构建结果需要在对应硬件上验证。

## 实现结构

页面使用 LuCI 原生视图和样式，通过专用 `zray` RPC 方法管理节点及主开关。节点保存在权限为 `0600` 的 UCI 配置文件中。链接解析使用浏览器的 URL、URLSearchParams 和 Base64 功能。

设置任务使用文件锁串行执行，读取最新保存的设置。代理进程由 procd 管理，以独立的 `zray` 用户运行。转发规则使用独立的 nftables 表，并随防火墙重新加载。加密 DNS 由独立的 zray-dns 服务运行现有 https-dns-proxy 二进制，通过当前节点发送请求；插件统一管理 DNS 转发配置，避免全局服务重复联动。启动节点所需的 DNS 查询使用单独配置的解析服务器。

Passwall 参考版本为提交 `9815bf90e9213d872845a19b5922547ee3d80d89`，主要参考主开关、节点选择、状态区和节点列表的交互组织。新增实现按本仓库 MIT 许可证提供。
